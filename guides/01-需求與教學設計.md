# 需求與教學設計大綱

## 1. 把需求定義清楚

目標是持續生產「讓學生先形成想法、設計測試、依證據修正解釋」的 S4 BYOD 互動學案，並把可觀察過程轉成教師能判讀的紀錄。

| 模組 | 每節課必須產生的結果 | 本原型的實現 |
|---|---|---|
| 教材對齊 | 書名、章節頁碼、先備概念、目標與來源 | 學案 JSON 的 textbook、reading、objectives 等欄位；示範待補教材 |
| 探究任務 | 可測試、容許學生先有不同想法的問題 | 情境問題、預測與理由 |
| 實驗設計 | 研究量、控制量、預定測試值與反證條件 | 研究變量選單及計劃文字 |
| 仿真實驗 | 可信模型、可拖動變量、數值與單位 | 合力與質量滑桿、小車動畫、a 與位移 |
| 證據整理 | 保留多次測試、比較公平性、圖表 | 實驗表格及按控制量分色的散點圖 |
| 解釋與遷移 | 主張、證據、推理、反思、新情境 | 分開的回答欄位與修訂紀錄 |
| 學習分析 | 教師知道誰卡在哪裏及應追問甚麼 | 完成度、過程分、提醒、完整時間線 |
| 課堂運維 | 收數據、補傳、備份與封存 | SQLite、事件去重、JSON/CSV、結束與重開課堂 |

目前示範是物理「合力、質量與加速度」。正式教材尚未提供，不能聲稱已符合你的課本或考綱。收到教材後，先改教學任務，再驗證模型，不先把所有章節套進同一實驗。

## 2. 一節 45 分鐘的建議安排

| 時間 | 學生做甚麼 | 教師觀察甚麼 |
|---|---|---|
| 0–5 分鐘 | 讀指定課本段落，理解情境與量的定義 | 是否混淆合力、質量、加速度與速度 |
| 5–10 分鐘 | 先預測，寫理由、研究量、控制量及測試值 | 預測可否被測試；甚麼證據會推翻預測 |
| 10–25 分鐘 | 至少三個水平的公平比較，必要時補做測試 | 每次改變是否有目的；是否同時改兩個量 |
| 25–35 分鐘 | 分析圖表，以自己數據寫主張／證據／推理 | 數據與主張是否相符；是否理解成立條件 |
| 35–42 分鐘 | 修正想法、作遷移題，解釋模型限制 | 能否把關係用到未見情境 |
| 42–45 分鐘 | 提交、確認同步；教師選例討論與口頭追問 | 紀錄不足和概念困難分開處理 |

不能把探究式學案寫成「照步驟拉到 2、4、6，然後抄公式」。應讓學生自己選擇至少三個測試值、說明公平比較的理由，並解釋哪種結果會令他改變想法。教師可提供分層提示，但不要在預測階段先展示答案。

## 3. 如何看出學生有沒有思考

紀錄只能提供證據線索，不能讀取學生心智。也不能僅因操作少、時間短或預測錯誤就判斷「沒思考」。課外準備、閱讀能力、裝置問題、無障礙需求都會影響操作節奏。

| 可見證據 | 可以支持的判讀 | 需要追加的確認 |
|---|---|---|
| 實驗前有預測及理由 | 留下了初始想法 | 讓學生說明理由和可反駁條件 |
| 同一控制量下有多個研究值 | 有公平比較的操作紀錄 | 是否事先設計，或只是碰巧點到 |
| 引用本人兩次實驗數字及單位 | 把數據用於論證 | 為甚麼這兩次可比較，其他次為甚麼不可 |
| 新證據後修改解釋 | 有修訂行為 | 修改是否有因果理由，而非只換句子 |
| 能解釋未見情境 | 有遷移表現 | 換一組條件口頭追問，避免只背答案 |
| 反思模型與實際實驗差異 | 理解證據的適用範圍 | 要求提出一項實物實驗可檢驗的偏差 |

建議的追問：「你為甚麼選這三個值？」「如果只看第 2 次和第 5 次，能下結論嗎？」「合力和質量一起變時，原先結論仍成立嗎？」「你會加做哪一個實驗來排除另一個解釋？」

## 4. 可覆核的評分框架

總分 100：系統過程指標 40 + 教師推理品質 60。自動分規則只按紀錄做判斷，文字是否有內容不等於推理正確。可把 40 分視為待教師覆核的形成性指標；特殊情況在評語補充，不用它單獨作高風險成績決定。

| 系統過程項目 | 分數 | 精確規則 |
|---|---:|---|
| 實驗前預測 | 10 | 後端順序中，首個 trial 前的最新 prediction 非空白 |
| 實驗前計劃 | 10 | 首個 trial 前的最新 plan 非空白 |
| 公平比較系列 | 15 | 按首個 trial 時選定研究變量分組，另一量完全相同，至少 3 個不同研究值 |
| 測試跨度 | 5 | 上述最大系列有至少 3 值，且最大值減最小值 ≥ max(最大值絕對值,1) / 2 |

跨度是本示範的教學啟發規則，並非跨學科通用科學評分標準。不同模型要重新定義。重複拖動不加分，重複執行完全相同條件不增加不同測試值數量。中途換研究變量會提示教師，過程分仍按首輪研究變量計算。

| 教師評分項目 | 滿分 | 高分表現 |
|---|---:|---|
| 預測與計劃合理性 | 15 | 預測可測、控制量清楚、有選值理由與反證條件 |
| 數據引用與比較 | 15 | 正確引用本人數據、單位、比較基礎，處理不公平比較 |
| 概念推理與限制 | 15 | 以科學概念連結主張和證據，清楚指出成立條件與仿真假設 |
| 反思與遷移 | 15 | 說明維持／修改想法的依據，能解釋新情境並設計驗證 |

每項 0／5／10／15 分可作參考錨點：無法判讀／有想法但依據薄弱／大致正確且有依據／論證充分並處理限制。教師控制台容許 0–15 的整數分，用於更細緻判斷。

完成度分成 5 個各 20% 的紀錄階段：預測＋計劃、至少三次實驗、分析＋主張＋證據＋推理、反思＋遷移、提交。這是有沒有完成記錄的量尺，不是知識掌握程度。

學生在評分後新增答案、實驗、研究變量或提交紀錄，舊評分會標為待重評，總分暫停顯示；僅滑桿調節不使已評答案失效。教師保存評分時若有新紀錄，系統拒絕覆蓋並要求刷新詳情。

## 5. 從試點到穩定使用

先讓 2–3 位學生測試登入與補傳，再試一個班。用首兩節課的實際答案校準評分規準；抽取高／中／低表現共同評閱，避免只看自動分。確認校內平板能連 GitHub 與 ngrok、課堂保留期限及資料管理規則後再擴大。

之後才考慮多教師帳戶、學校身分登入、雲端常駐後端、自動教材擷取、多模型庫、可靠離線載入與備份還原介面。AI 可以協助起草或提出評分建議，但本原型不把學生文字傳給 AI 服務，也沒有自動判斷學生思考或誠信的功能。
