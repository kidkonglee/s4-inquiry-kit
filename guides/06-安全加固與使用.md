# 安全加固與使用

加固日期：2026 年 11 月 19 日。學生繼續使用 <https://kidkonglee.github.io/s4-inquiry-kit/>。

本次實際驗證：Mac 防火牆已開啟、隱形模式已開啟、FileVault 已開啟；目前運行專案專用 Python 3.13.18。真實 GitHub Pages 的完整瀏覽器回歸測試通過，包含斷線補傳、提交、教師評分、修訂重評及權杖儲存檢查。公網 /teacher 回傳 404，教師端移至 8001；ngrok 路徑白名單與限流政策已啟用。

## 已實作的保護

| 範圍 | 新設定 |
|---|---|
| 公網入口 | ngrok 只轉發 127.0.0.1:8000；路徑只允許 /api/health、/api/join、/api/me、/api/events |
| 教師控制台 | 改為 <http://127.0.0.1:8001/teacher>，不經 ngrok 公開；仍需教師金鑰 |
| 伺服器 | Flask + Waitress；取消原本的 http.server；兩個本機監聽器均不綁定區域網路地址 |
| 連線與大小 | 每入口 8 個工作執行緒、64 個連線；請求主體最多 256 KiB、標頭最多 16 KiB，閒置連線會逾時 |
| 速率 | 學生入口全局每分鐘 2400 次；登入每分鐘 180 次；每位學生每分鐘 120 次；教師金鑰失敗每分鐘 20 次後暫緩 |
| 儲存 | 每學生每節課最多 5000 事件、300 次實驗、2 MB 事件內容；資料庫及 WAL/SHM 合計約 512 MiB 安全容量檢查；全系統最多 1000 課堂 |
| 登入權杖 | 雜湊保存、12 小時有效；每位學生最多保留 3 個有效登入權杖；教師金鑰只留在頁面記憶體，學生權杖改放當前分頁 sessionStorage |
| 請求驗證 | 管理入口限制 Host 與來源；不使用代理標頭作權限判斷；嚴格 JSON、數字、欄位與步長驗證 |
| 瀏覽器防護 | 教師頁 CSP、防嵌入、安全標頭；學生頁限制腳本與連線來源，避免把答案傳到未列出的外部服務 |
| 私有檔案 | private/ 目錄 700、檔案 600；服務建立新檔時使用 umask 077；教師金鑰與資料不在 GitHub 或 ZIP |

上述限制是單一小班試點的安全預設，不代表已驗證可支援全校。學生碰到容量或頻率限制時，先匯出紀錄備份、聯絡教師，不要清除瀏覽器資料。限流失敗不會把未完成的一批事件部分寫入；已成功接收的相同事件可重傳去重。

## 每天如何啟動

本機已安裝專案專用 Python 3.13.18 與 .runtime-venv，不影響 Homebrew 或其他程式原本的 Python。先開終端機：

```sh
cd "$HOME/Desktop/全世界/codex/s4-inquiry-kit"
python3 tools/start_server.py
```

另開終端機：

```sh
cd "$HOME/Desktop/全世界/codex/s4-inquiry-kit"
python3 tools/start_tunnel.py
```

第二個工具會先檢查 8000 埠沒有管理 API，再啟動隧道、關閉請求內容檢視、套用 ngrok-policy.json。**不要把 8001 埠交給 ngrok，也不要省略路徑與限流政策。** 自動啟動尚未設定；重啟 Mac 後需手動啟動。

教師金鑰仍在本機 `.env`。因為教師頁改到 8001，請重新登入；重新整理後也要重新輸入金鑰。學生關閉分頁後需要再次使用個別登入碼；已保存的答案與待傳事件另存於原裝置，同一學生重新登入可恢復。

更換 ngrok 網域時，須同步修改 docs/config.js、docs/index.html 的 connect-src、.env 的 ALLOWED_ORIGINS，並重新發佈前端。不要使用萬用字元放寬全部來源。

## 從 ZIP 或 GitHub 新安裝

先使用受支援且已更新安全修補的 Python，於專案根目錄：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python tools/init.py
python3 tools/start_server.py
```

若 `.env` 已存在，略過 init.py。下載包不含私密設定與資料，亦不包含龐大的 Python 執行環境。ngrok 請使用你自己的官方帳戶登入設定，勿向他人索取或分享 authtoken。

## 需要本人在 macOS 完成的部分

1. **防火牆與隱形模式**：本次已實際開啟並重新讀取設定驗證。日後如被關閉，可執行 `osascript tools/enable_firewall.applescript`，只在 macOS 的管理員授權視窗輸入密碼；以系統設定「網路 → 防火牆」實際狀態為準。
2. **獨立標準帳戶**：到「系統設定 → 使用者與群組」建立只運行本服務的標準帳戶。此帳戶不要設管理員權限，不登入個人 iCloud，不放私人文件。將程式、專用金鑰和資料搬到該帳戶可讀取的專用資料夾，重新設定自己的 ngrok 登入，再運行上述兩個工具；舊帳戶的服務應先停止。未完成此遷移前，服務仍共用目前日常帳戶的檔案權限。
3. **macOS 安全更新**：在「一般 → 軟體更新」確認安全更新；如需重新開機，先確認學生已同步並備份。
4. **共享服務**：在「一般 → 共享」關閉不用的遠端登入、螢幕共享、檔案共享及遠端管理。不要為學案另開路由器端口轉發。

系統密碼不應交給程式或貼到聊天。FileVault 已確認開啟，但它主要保護離線磁碟資料，不等於能阻擋線上程式漏洞。

這台 Mac 裝有 Docker Desktop 4.38.0，但 daemon 未運行，本次未啟用它。若之後採用容器隔離，應先更新至現行受支援的安全修補版，再只掛載教學資料目錄、以非 root 使用者及唯讀根檔案系統運行；不要掛載整個家目錄或 Docker socket。Docker 官方曾修補可導致容器存取主機資料的漏洞，因此不能把啟動舊版 Docker 當作安全加固。[Docker 官方安全公告](https://docs.docker.com/security/security-announcements/)

## 下課與備份

學生全部同步後結束課堂、匯出 JSON/CSV，執行 `python3 tools/backup.py`。備份另存到學校核准的位置。確認備份後停止 ngrok（在啟動隧道的終端機按 Control+C），不需要時停止後端。GitHub 學案仍可讀，但停止服務後不接收新紀錄。

## 已驗證與實際限制

16 項測試涵蓋公網管理入口封鎖（包含正確金鑰及偽造代理標頭）、Host／Origin、登入、JSON／大小限制、限流、容量、學生隔離、重傳原子性、評分及資料持久化。執行：

```sh
.runtime-venv/bin/python -m unittest discover -s tests -v
```

當次 `pip-audit -r requirements.txt` 沒有發現已知套件漏洞。這不代表自訂程式已接受第三方滲透測試，亦不保證未來套件沒有新漏洞。

仍有的限制：沒有獨立作業系統帳戶／虛擬機隔離前，程式若被入侵，可能影響執行帳戶可讀的資料；限流不能保證抵擋大規模 DDoS 或避免 ngrok 用量耗盡；本機睡眠、斷網與 ngrok 重新連線仍會影響可用性。只用代號保存學生資料，依學校規定處理保存期限及存取權限。
