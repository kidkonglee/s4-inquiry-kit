# 每節課如何批量生產探究學案

## 1. 工業化的是流程與品質，不是把每課換個標題

固定「教材輸入 → 教學設計 → 模型選擇 → 生成結構化學案 → 自動驗證 → 教師覆核 → 小規模試用 → 版本發佈」流程。網頁、資料上傳、教師控制台與記錄格式重用；每課的探究問題、可操作變量、模型假設、證據要求和遷移題必須重新設計。

目前原型已具備 JSON 學案、目錄、驗證上架工具與單一 newton 仿真模型。它不是已接好 AI API 的無人自動出題服務。下面的提示詞可以交給你選擇的 AI 工具使用，再經教師覆核；不需要把 API key 寫入網站。

## 2. 教師每課填寫的輸入表

```text
科目／年級：
課本名稱、版次、章節、頁碼：
本課指定閱讀段落或教師概述（只提供有權使用的內容）：
課時、班別人數、平板／瀏覽器條件：
先備知識、常見迷思：
2–3 個可觀察學習目標：
要探究的核心關係：
學生可改變的量、範圍與單位：
必須控制的量：
仿真模型的物理／科學根據及來源：
模型忽略甚麼、哪些情況不適用：
期望學生引用甚麼證據：
遷移題希望測到甚麼理解：
需要的語言支援／分層提示：
學案 id 與版本：
```

不要先把整本課本直接發佈到公開 GitHub。公開 JSON 用教師自行撰寫的任務、閱讀指引和頁碼；學生使用合法課本閱讀指定內容。若要放課文或圖片，先確認權限。

## 3. 可以直接使用的生成提示詞

把上表及 `docs/lessons/newton.json` 的完整結構提供給 AI，使用以下提示詞。此模板限定同一個力學模型；其他題材使用下一節的模型擴充流程。

```text
你是 S4 探究教學設計者。請根據我提供的教材資料，起草一份繁體中文、可讓學生自主探究的互動學案。

本次執行環境只支援 newton 模型：水平、由靜止出發、恆定合力 F、正質量 m；a=F/m，觀察時間2秒，s=0.5*a*t^2。不含摩擦分項與測量雜訊。F 是合力，不可把它描述成尚未扣除摩擦的拉力。不要生成或執行任何 JS、HTML 或 Python。

先檢查本課是否真的適用這個模型。若不適用，清楚說明需要的新模型與變量，不要硬套、不要輸出假裝可運行的學案。

若適用，先列出教材對齊表、核心迷思、探究路徑與教師參考答案，並另外輸出一個可另存為 JSON 的物件。教師參考答案與評分參考不可放入公開學案 JSON。

要求：
1. 探究問題可被比較測試，留有學生形成不同初始預測的空間。
2. 要求學生在實驗前寫預測、概念理由、研究變量、控制變量、自選至少3個值及可反駁條件。
3. 不提供逐格照做的食譜；讓學生選值、比較公平性、設計補充測試。
4. 主張、證據與推理分開；證據必須引用學生本人實驗的編號、數值及單位。
5. 反思不只問「學到甚麼」，要追問哪一個數據改變／支持原想法，以及下一個驗證。
6. 遷移題要改變情境或同時改變兩個條件，要求解釋與驗證方案。
7. 預測階段不洩漏正確結論；模型限制可以明示。
8. 不編造課本頁碼或來源。缺資料標明「待教師補充」。若來源與教材不同，說明用途。
9. 課時為1–180分鐘整數；用簡短清楚的繁體中文。
10. JSON 僅使用我提供的欄位，id 用新的英數字／連字號，model 固定 newton。force 與 mass 都必須含 min/max/step/initial；min<=initial<=max，初值與上限對齊步長，force.min>=0，mass.min>0，上限<=1000。
11. objectives 至少一項。保留 title、subject、duration、version、textbook、reading、question、predictionPrompt、planPrompt、analysisPrompt、reflectionPrompt、transferPrompt、modelNote、source 等欄位。
12. 最後給教師3條口頭追問題，及至少2個可能出現但不代表未思考的操作模式。

以下是本課教材輸入：
[貼上教師輸入表]

以下是 JSON 結構範本：
[貼上 newton.json]
```

## 4. 驗證與上架

1. 把 AI 輸出的純 JSON 存成一個新檔，去掉 Markdown 的三個反引號。教師答案另存於私人教案，不要放入 `docs/`。
2. 用文字編輯器檢查所有教材事實、單位、問題是否可探究、模型是否吻合。AI 提供的引用也需要核對。
3. 在專案根目錄執行，將路徑換成新學案檔案：

```sh
python3 tools/add_lesson.py /absolute/path/to/new-lesson.json
```

4. 工具檢查必要欄位、模型、變量範圍與步長、課時及重複 id。通過後會把學案複製到 `docs/lessons/` 並加入 `catalog.json`；重複 id 會拒絕。這只驗證結構，不能判斷教學品質或科學真確性。
5. 開啟 `http://127.0.0.1:8000/?lesson=NEW_LESSON_ID` 預覽。用滑桿最小、中間、最大值核對計算、動畫與表格。尤其檢查零合力、正質量以及控制變量系列。
6. 教師端建立測試課堂，選新學案；由預測一直做到評分。每個真實課堂建立時會把完整學案快照保存到資料庫，之後修改公開 JSON 不會偷偷改變已建立課堂的模型與任務。
7. 執行後端測試，並手動檢查新課題的教學有效性：

```sh
python3 -m unittest discover -s tests -v
```

8. 將新學案與目錄變更推送 GitHub；以新 id 發佈修改版，保留舊課堂快照。
9. 正式上課時選正確版本建立新課堂。學生登入後以後端的該課堂學案快照為準，避免網址指向錯學案。

## 5. 擴充其他模型時必須完成的工作

新科目不能只叫 AI 寫一條任意公式交給瀏覽器 eval。固定允許的模型清單，以程式實作並核對來源。

例如電路要先確定串並聯拓樸、元件理想化與可調參數；化學速率要說明使用近似模型的條件；生物種群模型要區分模型推演與真實生物實驗的推論。

每個新模型至少需要：

- 經教師確認的變量、單位、範圍、控制量及適用條件。
- `backend/core.py` 的模型白名單與參數驗證，以及伺服器重新計算結果。
- `docs/app.js` 和網頁中的變量控件、圖表、動畫／仿真呈現。
- 適合該模型的過程分規則，不能直接套力學的跨度分。
- 已知解、邊界與極限情況測試，及實際學生使用的可理解性驗證。

多個模型穩定後，才建議把介面改成可配置的變量列表與模型註冊表，再批量化不同章節。現有原型先驗證教學和數據流程，避免過早宣稱可自動生成所有科目的可信仿真。
